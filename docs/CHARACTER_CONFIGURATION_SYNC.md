# 角色配置同步与工作台

## 游戏内流程

1. 在 AssimpLoader 的 Model Workbench 导入 FBX，打开 `Character / RigWorks`。
2. 编辑人物比例、朝向、XYZ 根变换、人体骨骼映射、参考轴校准和原版动作到模型 clip 的映射。右侧内容可滚动；预览使用独立 GPU 视口，不修改 FBX。
3. `Apply` 启用此角色；`Save` 保存完整人物配置。`Equipment transform` 进入实际游戏画面的左右手装备编辑器。
4. 上传配置默认开启。导入后应用、保存、角色重新加载、专用动作包变更会触发内容检查；哈希未变化时不上传。修改后有短暂合并等待，网络忙时可见重试状态。
5. 服务器接受后返回权威配置版本与包哈希。其他客户端下载缺少的版本，校验成功后只重新建立对应角色的动画实例。

`Upload configurations` 关闭时保留本地角色和作者配置，停止发布私有选择，并撤回服务器上的自定义外观。已经开始但尚未确认的上传也不能重新启用展示。此选项不会删除其他人先前取得的缓存。

`Display other characters` 同时控制其他角色的下载和应用；关闭后使用原版人物。自己角色仍可在本地编辑、预览。服务器没有 RigWorks 通道时，编辑功能保持可用，并显示仅本地生效状态。

## 本地选项的运行时保存

`rigworks-client.toml` 的游戏内修改通过 `RigWorksConfig.update(...)` 提交完整配置事务。事务先复制并校验当前有效配置，再在同一目录写入临时文件并替换正式文件，最后刷新 Forge 配置缓存和事件。角色选择与启用可在一次事务中提交，修改上传开关或动画模式不会丢失已选择的模型、接触设置及其他选项。

RigWorks 只替换自己这个文件的监听回调；回调安排到客户端线程，与游戏内修改使用同一个事务锁，避免 NightConfig 的逐键自动保存和 Forge 热重载清空配置同时发生。格式不完整的外部 TOML 编辑保留当前有效配置并记录失败，修正后可继续热重载。支持原子移动的文件系统使用原子替换；其他文件系统退回同目录替换，监听读取仍受事务锁保护。

开发者应使用 `RigWorksConfig.update(edit -> edit.set(RigWorksConfig.CLIENT.enabled, true))`。不要在其他入口直接调用 `ConfigValue.set()` / `save()`，否则会重新引入同一份 NightConfig 数据的并发修改。

## 快照内容

`CharacterVisualConfig` 是不可变的 schema v1 快照，包含：

- 完整 `CharacterProfile`：模型资源 ID、比例、前向角、人体骨骼映射、参考旋转、原版姿势校准旋转、动作映射、头部和动作时间设置。
- 完整装备定义：左右手挂点、命名 sockets、按物品/tag/状态/使用动作/视图匹配的规则、双手接触 grips。
- XYZ 根偏移、XYZ 旋转、各轴独立比例。
- 内联求解器 rig、骨骼变形、动作和物理 sidecar 定义。
- 接触 IK、视觉物理、接地与角色效果选项。
- 模型原文件 SHA-256。

不发送编辑相机、编辑器布局、每帧骨骼矩阵、FBX、贴图、声音或原生库。装备或人物的视觉变换不会更改服务器碰撞箱、攻击距离和移动规则。

模型哈希当前只标识模型原文件，不证明外部贴图内容一致。接收端必须拥有相同资产；缺少资产、骨骼不匹配或哈希不符时保留原版人物并记录诊断。外部 FBX 在本机经工作台登记为稳定资源 ID，登记表不上传；其他客户端需要导入相同项目或安装匹配资源包。

## 专用 JSON 与动作脚本包

作者文件位于 `kubejs/rigworks/<avatar>/`，目录格式及脚本 API 见 [AVATAR_BEHAVIOR_RUNTIME.md](AVATAR_BEHAVIOR_RUNTIME.md)。它独立于 KubeJS 全局 `client_scripts`：

```text
manifest.json
mappings.json
controller.js
```

`CharacterAvatarBehavior` 自动发现本地包，为 `CharacterVisualSharing.packageFactory(...)` 提供作者源，并用 `CharacterPackageClient.installer(...)` 接收已校验包。接收的源码只进入专用受限解释器；不会写入作者目录，也不会注入 KubeJS 的全局环境。

本地与远端 `LocalPlayerCharacter` / `RemotePlayerCharacters` 均持有独立 `OwnerAvatarSession`。每个 owner 拥有自己的解释器、JSON 状态、输入历史与动作层；脚本在客户端 tick 中执行一次，渲染和阴影路径只消费已完成姿态。切换包只替换对应角色，脚本异常恢复内置动作。`SCRIPTED` 模式优先使用专用包，没有专用包时本地保留原来的 KubeJS 注册流程。

`CharacterAvatarBehavior.diagnostics(ownerUuid)` 返回源码哈希、controller、调用数、运行状态和失败原因。作者包刷新失败保留最近有效版本；收到脚本在初始化阶段失败时不会替换已安装包。

## 网络与持久化

通道为可选的 `rigworks:appearance` v2。服务器通过实际连接确定 owner UUID，客户端不能代替他人提交，也不能指定接受版本。

服务器目录通知包含人物元数据、整体 revision、独立 `configRevision`、显示配置摘要、配置包摘要和世界身份 UUID。只有下载请求后才发送配置包。普通飞行元数据变化不会使装备编辑的配置版本过期；配置提交必须匹配当前 `configRevision`。冲突先返回当前目录再报告拒绝，本地草稿不会覆盖接受状态。

登录、重连、重生、跨维度和开始跟踪玩家都会取得目录。已接受配置保存在世界 `data/rigworks_visuals.dat`；较大配置使用 UTF-8 字节数组，避免 NBT 单字符串的 65535 字节限制。退出保留世界配置，连接临时队列则清理。

提交完成后，目录发送失败不会撤销服务器记录，也不会把成功提交报告成拒绝。每个接收者独立发送，失败目录进入有界、按接收者和角色合并的退避队列；重试时重新读取当前版本，检查原连接和当前维度。只处理失败项，不定时全量广播。确认消息晚到或重复时仍可结束匹配的本地等待事务。

传输和缓存：

| 项目 | 当前限制或位置 |
| --- | --- |
| 显示配置 | 128 KiB；限制深度、成员、重复字段、有限数值与求解器工作量 |
| 完整配置包 | 512 KiB，最多 32 个 JSON/JS 文件，每个最多 64 KiB |
| 传输分块 | 有序 16 KiB；校验长度、顺序、压缩字节哈希和解码后的规范包哈希 |
| 上传节流 | 每连接至少间隔 4 tick；拒绝和超时均有状态，客户端保留最后改动并有限重试 |
| 服务器缓存 | `data/rigworks/packages/<hash>.bin`，预算 128 MiB |
| 接收端缓存 | `kubejs/rigworks/cache/<world-identity>/<hash>.bin`，预算 64 MiB |
| 客户端并发下载 | 最多两个，缓存读取、解压和哈希在有界后台任务执行 |

缓存是带版本头的 gzip 二进制容器。接收端不落盘明文 JSON/JS，旧有效缓存保留到新包验证成功。缓存淘汰保留当前安装和目录引用的包。压缩不是加密，不提供防提取保护，也不是零拷贝。

## 性能与应用边界

根变换、相同挂点的装备变换只更新矩阵；结构性 rig、动作映射、物理或包改变时只重新建立该 owner 的动画实例，复用已导入的模型。模型文件哈希在加载工作线程计算并按资源代次缓存，渲染循环不逐帧读文件。网络只传配置变更和原版没有提供的轻量显示状态。

界面区分“包已校验，正在应用模型”和“角色配置已应用”。下载或脚本初始化失败时明确提示保留旧有效角色，或者没有旧实例时使用原版。相同 profile、同一世界与资源代次的配置重载保留旧 live binding，新模型哈希、装备节点、rig 与物理初始化成功后再交换。旧实例的根变换继续取自旧实例配置；新配置验证失败不会把其偏移应用到旧几何上。更换 profile、切换世界、资源整体重载或旧实例已损坏时不能保留该实例，会使用原版并显示原因。包缓存验证与模型实际安装仍是两个阶段，不承诺跨脚本、原生状态及首次 GPU 绘制的完整原子事务。

RigWorks 工作台扩展声明自己拥有角色应用，避免通用工作台对共享 `AssimpScene` 施加全局变换后，再叠加 owner 私有变换。人物使用上述完整快照；通用工作台的任意材质和节点编辑不自动变成多人角色配置。

## 验收边界

单元测试覆盖配置完整往返、严格 JSON、配置与飞行版本分离、旧版本拒绝、撤回展示、持久化、大于 64 KiB 的 NBT 配置、包路径/大小限制、乱序或损坏分块和二进制容器。专用脚本另有真实 Rhino 的隔离与预算测试。

失败目录补发另有队列测试：最新版本合并、确认请求保留、连接替换、指数退避、队列容量和断线清理。

`RuntimeConfigFileTest` 使用真实 NightConfig TOML 与自动保存对象，覆盖并发热重载期间的完整事务、模型及无关选项保留、嵌套修改校验失败不污染旧配置、损坏 TOML 保留旧值及随后恢复。

2026-11-18 已在两个独立开发客户端和集成 LAN 服务器中通过：首次发布与后台下载、真实远端脚本执行、关闭/重新开启他人角色显示、修改左右手装备和角色根变换后同步第二版、对应脚本替换、二进制缓存解码与哈希校验。接收端最终有一个有效远端 binding，已实际绘制，未报告失败。测试使用离线开发身份；关闭认证仅发生在显式启用的测试入口及一次性世界中。

工作台导入、GPU/PBR 预览、撤销/重做、挂点选择回归、保存以及 GUI 缩放 2/3 已在实际客户端执行。详细证据及截图见 [本轮验收记录](RIGWORKS_SHARING_VALIDATION_2026-11-18.md)。

独立专用服务器、正常认证登录、断线重连、跨维度、较多玩家及不稳定网络仍需另行验收。本轮静态截图不证明所有光影下的运动画面，也不作为性能基准。
