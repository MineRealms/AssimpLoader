## 目标与边界

玩家导入 FBX 与可用贴图，在 Minecraft 中预览、编辑、应用和保存配置。JSON 由 Mod 维护，不要求普通玩家手填重复数据；Blender 导出脚本是可选作者工具。

数据流：`源模型 -> 只读 Assimp Scene -> 元数据 + 不可变编辑草稿 -> 本地运行时或模块扩展`。不回写源网格、UV、权重和动画关键帧，复杂创作继续使用 DCC。

| 模块 | 职责 |
| --- | --- |
| AssimpLoader | 导入、项目文档、通用视口/Inspector/Gizmo、材质、Socket、动画预览、事务、保存与扩展 API |
| RigWorks | 人体映射、原版动作/校准、双手装备、角色配置和按玩家分享 |
| 后续车辆、炮塔模块 | 注册自己的扩展面板、验证器与应用器，复用通用 GUI |
| 服务端 | 接受、保存和分发版本化角色配置；模型资源文件分发另行处理 |

## 本地应用与性能

- [x] 复用 Scene、驻留 VBO、骨骼矩阵缓冲和材质缓存；CPU 采样与 GPU 顶点蒙皮分工。
- [x] 数值材质编辑使用 Uniform，贴图改变只更新对应材质变体。
- [x] 独立预览拥有 normal/specular GPU 纹理缓存，不依赖 Oculus 子纹理；来源替换、关闭/切换和资源重载时释放，不逐帧重传。
- [x] 变换拖动不重新导入 FBX、不重建全部几何、不每帧写 JSON，不要求 F3+T。
- [x] 独立预览不重复驱动世界声音、粒子或实体行为。
- [x] IO 有界队列，GL 创建/销毁留在渲染线程，关闭时释放专用预览资源。
- [x] 普通资产按来源本地应用；RigWorks 接管按玩家配置，避免双重根变换。
- [ ] 普通资产按具体实体/实例应用、应用清单管理、启动后自动恢复应用绑定。
- [ ] 完整证明编辑不重复上传几何，并完成实际光影/无光影性能验收。

## 配置共享与一致性

| 数据 | 当前处理 |
| --- | --- |
| 相机、选择项、历史、未确认草稿 | 仅本地 |
| RigWorks 比例/根变换、骨骼/动作映射、装备及规则、Rig/物理/选项 | 通过角色配置包与服务器接受版本分享 |
| Avatar JSON/JS 行为源 | 有界包、内容哈希、压缩缓存和隔离运行时；不进入全局 client_scripts |
| 原版移动、持物、挥手、使用 | 复用 Minecraft 状态同步，客户端逐 owner 计算姿态 |
| 通用任意节点/材质/Socket 覆盖 | 尚未通用网络同步 |
| FBX、贴图和模型资源 | 本轮不分发，接收端需有匹配资源和哈希 |
