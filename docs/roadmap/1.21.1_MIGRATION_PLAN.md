# AssimpLoader 升级 Minecraft 1.21.1 实施计划

> 状态：待启动（评估已完成，见对话记录与本文第 0 节结论）
> 目标：在保留 1.20.1 能力的前提下，新增 Minecraft 1.21.1 支持；版本差异尽量用兼容层吸收，Mixin 按 1.21.1 重写目标。
> 估算：1 人 3~5 周（双版本），单版本约 2~3 周。

---

## 0. 前提与决策

### 0.1 评估结论（已核实）

- 项目 58k 行中约 2/3（动画、物理、模型、序列化）**版本无关**，可直接移植。
- 断点集中在：渲染层、客户端渲染 API、`ResourceLocation`、构建链、第三方兼容。
- 1.21.1 事实：Forge 官方存在（`1.21.1-52.1.21`）、NeoForge `21.1.267`、Java 21、LWJGL 3.3.3、资源包 pack_format 34。
- 关键依赖：Oculus **无** 1.21.1（需换 Iris NeoForge 原生）；Photon / LDLib / Embeddium / KubeJS / Rhino 均有 1.21.1 版本。ModernUI 虽有 1.21.1 版，但其代码经核实为**死接线**，本次直接下线（见阶段 7）。
- 工作区惯例：NodalMechanics、Isorropia、Thaumaturge 均采用 `versions/1.21.1-neoforge` + stonecutter 多版本结构。

### 0.2 默认决策（若用户另有选择，按对应备注调整阶段）

| # | 决策 | 默认取值 | 影响 |
|---|---|---|---|
| D1 | 版本策略 | **双版本**：保留 1.20.1 Forge，新增 1.21.1 NeoForge | 阶段 3 必做；单版本可跳过阶段 3 的多节点部分 |
| D2 | 1.21.1 loader | **NeoForge 21.1.x**（工作区惯例、生态最完整） | 若选 Forge 52.x，阶段 1/3/5 的 loader 相关项替换即可，渲染 API 改动量相近 |
| D3 | ModernUI 死接线（47 文件 + `nodeeditor/` 77 文件） | **直接下线删除**（用户 2026-11-18 决定），不保留、不适配 | 阶段 7 工时降至 0.5 天； ModernUI 依赖整体移除 |
| D4 | 光影通路 | Oculus → **Iris NeoForge 原生**（1.21.1 无 Oculus） | 阶段 5.1 必做 |
| D5 | Photon 集成 | **保留**，适配 2.2.x | `lookdev/nodeeditor` 已随 D3 删除；Photon 适配仅余 `compat/photon`、`mixin/photon` |

## 1. 总体策略

1. **先打通编译，再谈运行**：阶段 1-2 用单版本 1.21.1 把编译错误清零，成本最低、反馈最快。
2. **差异收进兼容层**：渲染 API、资源名、帧时间、第三方通路做成"接口 + 双版本实现"，共享 `src/` 不出现 loader 分支。
3. **多版本用 stonecutter**：`src/` 共享、`versions/<node>/src` 放适配器，避免 `//? if` 满屏都是。
4. **Mixin 按 1.21.1 重写**：目标类是原版的按新 mappings 核对签名；第三方目标按新版本包名/签名的条件化。
5. **每阶段可回滚**：阶段 1-2 在独立分支；阶段 3 之后双版本并存，1.20.1 始终可构建。
