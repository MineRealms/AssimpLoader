## 2. 实际源码与构建结构

- `settings.gradle` 创建两个 Stonecutter 节点，共享根 `build.gradle`。
- 当前编辑基线是 `1.20.1-forge`。共享 `src/` 使用 Forge 1.20.1 API；纯符号迁移由 `stonecutter.gradle` 的替换规则完成。
- 方法签名、接口形态等结构差异使用 `//? if forge` / `//? if neoforge` 条件块。生成目录不作为手工编辑入口。
- `ResourceLocations`、`MeshBuffers`、`ScreenCompat` 等已有工具吸收局部差异。不要求为了沿用早期计划，再创建一套同义的 `VertexWrites/MeshUpload/FrameTime` 抽象。
- `versions/<节点>/src` 存放模组元数据、pack.mcmeta 等版本资源。当前没有把全部 Java 差异拆成平台子目录。
- `main` 是通用引擎；`showcase` 是独立 AssimpShowcase 模组；`integrationTest` 是开发运行验收入口，不能进入发布 JAR。
- 引擎与 Showcase 单向隔离由 `gradle/module-boundaries.gradle` 校验。RigWorks 是独立仓库，本仓库不包含其发布代码。
- `buildAndCollect` 依赖两个节点的 `build`，全部成功后汇总到 `build/distributions/`。

常用命令：

```powershell
.\gradlew.bat :1.20.1-forge:build --console=plain
.\gradlew.bat :1.21.1-neoforge:build --console=plain
.\gradlew.bat buildAndCollect --console=plain
.\gradlew.bat :1.21.1-neoforge:runClient --console=plain
```

每个节点分别输出：

```text
versions/<节点>/build/libs/
  assimploader-<mc版本>-<加载器>-<模组版本>.jar
  assimpshowcase-<mc版本>-<加载器>-<模组版本>.jar
```

引擎发布 JAR 内含 Assimp 绑定、六平台原生库和物理库；Photon、LDLib、光影模组与 KubeJS 不捆绑。Forge 产物需要重混淆和 refmap，NeoForge 保持官方映射。完整构建和打包结果仍须按第 5 节验收。

## 6. 独立 RigWorks 迁移状态

已完成（2026-11-20）。RigWorks 仓库 `main` 采用相同的 Stonecutter 0.9.8 双节点与 ModDevGradle 结构，引擎作为固定提交的子模块消费，依赖方向严格为 RigWorks → AssimpLoader。

- 引擎子模块固定在 `a449d8c`，与本仓库 `multiversion` 当前 HEAD 一致。
- RigWorks 侧 `build.gradle` 的 `prepareAssimpLoader` 在引擎仓库构建匹配节点的**官方映射**开发 JAR；SRG 命名的发布 JAR 不直接作为依赖，避免运行期 `NoSuchFieldError`。
- `buildAndCollect` 汇总 `rigworks-<MC版本>-<模组版本>-<加载器>.jar` 到 RigWorks 的 `build/distributions/`，两个节点产物均已生成。
- 网络 Payload、SavedData、原版动作与装备、相机、KubeJS 2101 插件与 reload 事务钩子、配置包 catalog/request/chunk 与 digest 校验均已适配。
- 双节点测试与实机记录由 RigWorks 仓库维护：其 `docs/development/1.21.1_MIGRATION.md` 记录 Forge 191、NeoForge 196 项测试 0 失败 0 跳过，以及 NeoForge KubeJS smoke、客户端进入世界、工作台保存重开与装备编辑验收。本仓库未复跑这些测试，`RigWorks/versions/*/build/test-results/test/` 只是最近一次部分运行的残留，不作为计数依据。
- 仍待现场确认项见该文档：1.20.1 客户端 GUI 交互、真实键盘驱动的全动作矩阵、专用服务器/认证/跨维度、GitHub CI。
